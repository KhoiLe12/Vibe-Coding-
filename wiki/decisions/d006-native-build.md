# d006 — How the C++ core is built and shipped

*Status: accepted (2026-10-26, made during M0 build; human may revisit).*

## Context
[[d001-platform-and-stack]] calls for a shared C++17 core reached from Dart over `dart:ffi`. Flutter 3.47 offers two ways to ship native code. The plan does not say which.

## Options considered
1. `plugin_ffi` template — CMake for Android, CocoaPods/SwiftPM for iOS. Marked **deprecated** in Flutter 3.47.
2. **`package_ffi` template with a Dart build hook** (`hook/build.dart` + `native_toolchain_c`) — one Dart file compiles the C++ for every target; on by default in stable. **Chosen.**
3. Hand-written CMake + Xcode integration — most control, most upkeep. Rejected for now.

## Choice
- Layout: Flutter app in `app/`; the core is the local package `app/packages/pocket_audio/` (path dependency).
- miniaudio 0.11.25 is **vendored** (single header + impl), pinned, licence alongside.
- Apple targets compile miniaudio as Objective-C++ (`miniaudio_impl.mm`), because its iOS backend calls AVAudioSession. They define `MA_NO_RUNTIME_LINKING` and link CoreFoundation/CoreAudio/AudioToolbox (+ AVFoundation on iOS) directly, since miniaudio's runtime linking can fail Apple notarization.
- Other targets compile as C++; Android uses miniaudio's default AAudio → OpenSL ES runtime linking.
- Unused miniaudio subsystems (engine, node graph, resource manager, generation) are compiled out.
- Bindings are generated by ffigen from `src/pocket_audio.h` and committed.

## Consequences
- Host (macOS/Linux) `dart test` exercises the real C++ code, so CI can test the core without phones.
- Generating bindings locally needs libclang (Command Line Tools path works on macOS).
- If the M2 latency gate forces Oboe/AVAudioEngine ([[d001-platform-and-stack]]), they plug in behind the same C API; the hook gains per-OS sources.
- App identifiers: Android `applicationId` `dev.pocketstudio.pocket_studio`, iOS bundle id `dev.pocketstudio.pocketStudio`. **Placeholder** — confirm with the human before store listings (M8).
- CI: GitHub Actions (`.github/workflows/ci.yml`) runs wiki lint, core + widget tests, a debug APK build and an unsigned iOS build, with Flutter pinned to 3.47.8.
